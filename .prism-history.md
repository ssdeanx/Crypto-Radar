**Recommendations:** (1) Implement dual-output (primary `/data/crypto-radar/`, secondary `~/.hermes/data/crypto-radar/`) by threading second dataDir through `appendToLog()` + CLI scan handler. (4) Keep Docker improvements as known gap but don't block local deploy on them.

**Conservation law:** DataPathResolution × EnvDefaultCoverage = Constant. Every independently-resolved data path without a deploy-time env override reduces production readiness proportionally. Current: ~6 paths × 1 override = 6. Adding dual-output without override keeps 7 × 1 = 7.

**Conservation law (analysis):** ExternalDeploymentReadiness × LocalDataLifecycleHealth = Constant. Analysis that optimizes for generic deployment readiness misses local lifecycle issues, and vice versa. Product invariant at analyst's attention budget.

(5) Add dataDir startup log (F13). (6) Deploy requires registering Hermes cron on production machine with `RADAR__DATA_DIR=/data/crypto-radar`.

**Conservation law:** DefaultCorrectness × DeploymentConfigurationComplexity = Constant. Wrong default (~/.hermes/) forces operator to set env var. Right default (/data/crypto-radar/) works with zero config.
